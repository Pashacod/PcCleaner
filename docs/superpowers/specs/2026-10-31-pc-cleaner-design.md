# PcCleaner — утилита очистки ПК от мусора

Дата: 2026-10-31. Статус: спецификация на согласовании.

## Цель

Своя программа для Windows 11, сделанная ради опыта на новом стеке (C#/.NET/WPF).
Чистит то, что встроенная очистка Windows не трогает (кэши разработки, браузеров),
и помогает найти крупные файлы. Должна выглядеть как современная программа Windows 11,
а не как скрипт.

**Что сказал Павел:** цель — опыт и своя программа; стек C# + WPF + WPF-UI;
источники — Temp и корзина, браузеры, кэши разработки, большие файлы; дубликаты — во
второй версии; сначала показать, потом удалить (кэши насовсем, большие файлы в
корзину); программа всегда запускается с правами администратора.

**Допущения (мои):** пользователь — сам Павел, возможно друзья; один язык интерфейса —
русский; без автозапуска и расписания.

**Критерии успеха:**
- сканирование показывает размер мусора по категориям, окно не зависает;
- очистка освобождает место и честно сообщает, что пропущено и почему;
- ни при каких условиях не удаляется ничего из запрещённых путей (покрыто тестами);
- один .exe, который запускается на чужом Windows 10/11 без установки .NET.

## Не входит в первую версию

Дубликаты (v2, отдельным источником), очистка реестра, расписание, автозапуск,
трей, другие языки, установщик.

## Стек и сборка

- .NET 8 (LTS), C#, WPF, библиотека WPF-UI (lepoco/wpfui) — вид Windows 11, Mica,
  тёмная/светлая тема по системе.
- MVVM: CommunityToolkit.Mvvm.
- Тесты: xUnit.
- .NET SDK ставится в `D:\Program Files\dotnet` (ничего на C).
- Публикация: `dotnet publish` self-contained, single-file, win-x64 → один .exe
  (~70 МБ).
- Манифест: `requestedExecutionLevel level="requireAdministrator"` — UAC при каждом
  запуске, логики перезапуска с правами нет.

## Ядро: источник мусора

```csharp
public interface IJunkSource
{
    string Id { get; }            // "user-temp"
    string Title { get; }         // "Временные файлы"
    string Category { get; }      // карточка в UI: "Система", "Браузеры", "Разработка"
    string? Warning { get; }      // "Следующая сборка будет дольше" и т.п.
    bool CheckedByDefault { get; }
    Task<ScanResult> ScanAsync(IProgress<long> progress, CancellationToken ct);
    Task<CleanResult> CleanAsync(ScanResult scan, CancellationToken ct);
}

record JunkItem(string Path, long SizeBytes, bool IsDirectory, bool Selected);
record ScanResult(string SourceId, IReadOnlyList<JunkItem> Items, long TotalBytes);
record CleanResult(long FreedBytes, int Deleted, IReadOnlyList<SkippedItem> Skipped);
record SkippedItem(string Path, string Reason);   // "занят другой программой", "нет доступа"
```

Общий класс `FileDeleter` выполняет фактическое удаление для всех источников:
- насовсем — `File.Delete` / рекурсивно по папке, каждый файл в своём try/catch;
  занятый или недоступный файл попадает в `Skipped`, очистка продолжается;
- в корзину — `Microsoft.VisualBasic.FileIO.FileSystem.DeleteFile(..., SendToRecycleBin)`.

Перед каждым удалением `FileDeleter` спрашивает `PathGuard`.

## Защита: PathGuard

Жёсткий список запрещённых путей, проверяется на каждом удалении независимо от
источника. Путь нормализуется (`Path.GetFullPath`, регистр не важен, симлинки и
junction-точки не обходятся — удаляется сама ссылка, а не цель).

Запрещено удалять:
- корень любого диска;
- `C:\Windows` и всё внутри, **кроме** `C:\Windows\Temp\*`;
- `C:\Program Files`, `C:\Program Files (x86)`, `D:\Program Files`, `C:\ProgramData`
  (кроме явно разрешённых кэшей, если появятся);
- сами папки профиля и всё внутри: «Документы», «Рабочий стол», «Изображения»,
  «Видео», «Музыка», корень `%USERPROFILE%`;
- `.git` в любом месте.

Исключение: источник «Большие файлы» может отправлять в корзину файлы из профиля
пользователя (но не из системных папок) — только потому, что их выбрал человек вручную.

Нарушение → `SkippedItem("запрещённый путь")` и запись в журнал; это считается багом
источника.

## Источники v1

| Id | Категория | Что | Удаление | По умолчанию |
|---|---|---|---|---|
| user-temp | Система | `%TEMP%` | насовсем | отмечен |
| windows-temp | Система | `C:\Windows\Temp` | насовсем | отмечен |
| recycle-bin | Система | корзина всех дисков (`SHQueryRecycleBin` / `SHEmptyRecycleBin`) | системная функция | отмечен |
| chrome-cache | Браузеры | `Cache`, `Code Cache`, `GPUCache` в каждом профиле `%LOCALAPPDATA%\Google\Chrome\User Data\*` | насовсем | отмечен |
| edge-cache | Браузеры | то же для `Microsoft\Edge\User Data` | насовсем | отмечен |
| firefox-cache | Браузеры | `%LOCALAPPDATA%\Mozilla\Firefox\Profiles\*\cache2` | насовсем | отмечен |
| gradle-cache | Разработка | `%USERPROFILE%\.gradle\caches` | насовсем; предупреждение «следующая сборка дольше» | не отмечен |
| npm-cache | Разработка | `%LOCALAPPDATA%\npm-cache` | насовсем | отмечен |
| project-builds | Разработка | папки `build`, `.gradle`, `bin`, `obj`, `node_modules` в корнях проектов (по умолчанию `D:\Work`, список меняется) | насовсем | `node_modules` не отмечены, остальное отмечено |
| big-files | отдельная вкладка | топ-50 файлов > 500 МБ на выбранном диске | только в корзину | ничего не отмечено |

Браузеры: только кэш — пароли, история, cookies, закладки не трогаются. Если процесс
браузера запущен — источник возвращает предупреждение «Закройте Chrome» с кнопками
«Повторить» / «Пропустить».

`project-builds`: папка `build`/`bin`/`obj` считается мусором, только если рядом
лежит признак проекта (`build.gradle*`, `settings.gradle*`, `*.csproj`, `package.json`),
чтобы не снести чужую папку с таким именем. Внутрь `node_modules` при обходе не
заходим.

Корни проектов и порог «больших файлов» хранятся в `settings.json` рядом с .exe.

## Интерфейс

Одно окно WPF-UI, две вкладки: «Очистка» и «Большие файлы».

**Очистка:**
1. Старт: карточка диска («C: свободно 29 из 135 ГБ», полоска), кнопка «Сканировать».
2. Сканирование: все источники параллельно в фоне, каждая карточка-категория
   показывает свой прогресс; кнопка «Отмена».
3. Результат: карточки по категориям с галочкой и размером, раскрываются до
   источников и папок. Внизу «Выбрано: N ГБ» и «Очистить».
4. Подтверждение: «Будет удалено насовсем N ГБ. Продолжить?»
5. Итог: «Освобождено N ГБ», список пропусков с причинами (свёрнут).

**Большие файлы:** выбор диска, «Найти», таблица имя / папка / размер / дата
изменения, галочки, «Открыть папку», «В корзину».

## Ошибки

- Занятый файл / нет доступа → пропуск, счётчик в итоге, очистка не прерывается.
- Отмена → уже удалённое остаётся удалённым, итог показывает, сколько успели.
- Исключение в одном источнике → его карточка показывает ошибку, остальные работают.
- Журнал: `logs\yyyy-MM-dd.log` рядом с .exe — что сканировали, что удалили, сколько,
  пропуски, нарушения PathGuard.

## Тесты (Cleaner.Core.Tests)

На временных папках с подставными файлами, без реальной системы:
- подсчёт размера (вложенные папки, пустые папки);
- PathGuard: каждый запрещённый путь заблокирован, `C:\Windows\Temp\x` разрешён,
  обход через `..` и разный регистр не проходит;
- FileDeleter: занятый файл (открыт с `FileShare.None`) попадает в Skipped, остальные
  удалены; отмена через CancellationToken;
- project-builds: `build` рядом с `build.gradle` найден, `build` без признака проекта
  пропущен, внутрь `node_modules` не заходим, `node_modules` не отмечен;
- браузеры: на подставном дереве профилей находятся только папки кэша.

Источники принимают корневые пути через конструктор, чтобы в тестах подставлять
временные папки вместо `%TEMP%` и профилей.
